# Orbsie architecture

The client owns rendering, input, formation, game sessions and durable local drafts. Next.js routes own provider relaying, account-scoped cloud storage and deployment credentials. Creation uses available free prompts or a connected provider/account; deterministic fixtures are test infrastructure only. Public exports contain the standalone player, committed project and required assets, without editor credentials.

`src/lib/protocol.ts` defines the bounded project schema and operation envelope. Operations carry project/run identity, unique IDs, sequence and expected revision. Validation rejects malformed commands, unknown references, excessive complexity and nonfinite transforms. The reducer preserves unchanged entity references so scoped edits do not reconstruct unrelated meshes. Typed `game-program.ts` rules and `game-session.ts` interpret inputs, conditions, variables, timers and bounded actions in trusted code; model output is never evaluated as JavaScript. Legacy collection/platform/portal/bloom behaviors remain supported.

OpenRouter, AI Gateway and the local ChatGPT companion use the same authoring protocol. `authoring-history.ts` supplies at most eight complete recent messages and 8,000 text characters alongside the instruction and current scene, removing a duplicate trailing prompt and stale entity references. The API adapters buffer SSE text into complete newline-delimited records. Records are validated before application; partial JSON is never rendered. Catalog preflight rejects absent and known-incompatible API models before consuming free quota or starting inference. Unspecified capabilities stay unknown rather than being advertised as supported. ChatGPT uses an explicitly paired local companion; see `chatgpt-integration.md` for its boundary.

The persistent React Three Fiber canvas spans landing, descent and editing. `parcel-transition.ts` supplies a stable project parcel anchor and tangent frame; the world/camera transition and composer use coordinated progress. `Formation` interpolates position and color on the GPU. Compatible topology uses solid deformation; changed topology uses bounded area-weighted surface particles before solidification. An interrupted morph captures its current eased state for the next revision. Catalog and generated geometry decoders prepare particle attributes in workers, with bytes included in asset budgets. Procedural and worker-unavailable fallback preparation can still run on the main thread. Absolute material overrides recolor procedural, catalog and generated models without rewriting their geometry recipes. Browser evidence covers continuity and handoff, not universal aesthetic quality or normal-GPU performance.

The asset catalog stores permitted models with provenance and license files. Generation can mix catalog assets with procedural or newly constructed models; an explicit new-model request overrides reuse. The local modeling companion interprets bounded construction operations through isolated Blender execution and returns validated GLB data. Generated bytes persist locally and can be uploaded/restored through owner-scoped cloud storage. This working development executor does not yet constitute the required release-certified portable Blender distribution.

The generation store keeps the latest finished checkpoint through Stop, stream failure and later incomplete replacement. Connected generation journals persist validated operation sequences and recovery checkpoints. Recovery is explicit continuation from durable state, not resumption of a provider's interrupted stream. Controller/token and captured-project guards suppress stale callbacks. Local IndexedDB updates and Web Locks protect writes, with a visible per-project writer lease. Bounded undo/redo histories persist with project snapshots and create monotonic revisions. Cloud writes use owner checks, row locking and optimistic revision checks; explicit cloud recovery preserves divergent local branches before replacement.

`experience-metrics.ts` retains the latest 20 runs in browser memory, recording submission, reservation, early main-camera seed draw, active controls, objective readiness, generation completion and publish readiness separately. Unobserved times stay null; snapshots contain no prompts or credentials and cause no telemetry requests. See `evidence/experience-metrics/README.md` for exact semantics and limitations. Adaptive resolution caps fill rate and changes DPR after sustained frame-time windows; normal-laptop frame-time acceptance remains unverified.

Export packages the shared player, source, pinned dependencies, project snapshot, worker bundles, required catalog/generated assets and preserved licenses into an independent ZIP. Hash-based play links are a separate snapshot-sharing mechanism. Dedicated publication maps an Orb to a Vercel Project, serializes attempts and captures immutable release metadata. URL, revision, title, safe creator attribution and thumbnail promote together only after deployment/integrity verification under a compare-and-swap guard. A failed attempt preserves the prior public release. The stable sharing page reads promoted metadata rather than draft content. Pending status polling survives closing Share, but not closing the browser; no background promotion worker is installed.

Platform deployment, cloud storage and several real ChatGPT workflows have checked-in evidence. Dedicated per-Orb publishing remains blocked by token permissions. Astra OpenRouter/Gateway E2E still requires authorized funded access. The scope audit and provider-specific reports distinguish those unresolved gates from deterministic tests and historical model runs.
