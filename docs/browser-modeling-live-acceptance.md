# Browser modeling live acceptance

Use the existing `scripts/provider-browser-e2e.mjs` harness with `ORBSIE_REQUIRE_BROWSER_MODEL=1`. The gate requires at least one committed generated entity whose job backend and trusted model source are both `browser-manifold`, waits for the trusted baked GLB to be present and hash-verified in IndexedDB, and selects that entity for the harness's scoped edit. The default scoped edit remains a material recolor and is reported as `edit.type: "material"`.

Set `ORBSIE_CREATION_PROMPT` to explicitly request a new browser-manifold model, and `ORBSIE_REQUIRE_NEW_ONLY=1` when testing catalog bypass. Keep `ORBSIE_LIVE_E2E=1`, exact Luna model, provider-specific credential scope and authorized output cap explicit. Existing live-call opt-in and credential controls remain in force. Users' model choices remain unrestricted by this test policy.

For a real recipe edit, set `ORBSIE_REQUIRE_GEOMETRY_EDIT=1` and provide an explicit geometry `ORBSIE_EDIT_PROMPT`. This requires browser modeling and checks the same selected entity ID, every non-geometry entity field, unrelated entities, browser provenance, increasing recipe revision, and a different hash for the trusted baked GLB. The report identifies this as `edit.type: "geometry"`.

For the full revolve acceptance, also set `ORBSIE_REQUIRE_REVOLUTION=1`. This requires `ORBSIE_REQUIRE_NEW_ONLY=1`, verifies the created target recipe contains a full revolve, and checks that the geometry edit increases profile and mesh X width while preserving the explicit Y bounds. Segments default to 32 and remain capped at 64; partial sweeps are unsupported.

The default scoped edit preserves geometry and changes material; reload, export and optional publication retain the harness's existing checks. Fixture editor evidence in `docs/evidence/browser-modeling-editor-resume` proves local creation/edit/reload, not live model behavior. The deformation sibling in `docs/evidence/browser-modeling-editor-deformation` proves bounded twist and taper revisions, and `docs/evidence/browser-modeling-editor-variation` proves seeded variation, through the same editor and worker path.

OpenRouter retains the authorized 512-output-token test cap. Gateway BYOK live acceptance awaits a configured `AI_GATEWAY_TEST_KEY` with available credit; historical server-funded free-prompt tests do not substitute for it. ChatGPT subscription connection remains a top priority: production device-code issuance and cancellation are verified, but user consent and live generation are pending. Tests must use Luna with regular processing; local companion tests do not satisfy browser-only acceptance.
