The public revision-9 page and its exact project and catalog assets load in signed-out Android Chrome, and the island, tree, and crystal render. Touch-camera movement remains unverified after two canvas drags, including one from an unobstructed area of the world canvas. Both harness runs are preserved separately and report `failed` at the touch-change assertion.

The first clean Android 15/API 35 non-Play AVD stopped at Chrome's first-run Terms of Service screen. No agreement or data-sharing choice was accepted. A separate copy of the already-initialized API 35 AVD was then used, leaving the original AVD untouched. The clone had no Android accounts. Its `orbsie.com` cookie was removed only in that clone before the first run. On the targeted rerun, Chrome was rechecked on `about:blank` with zero cookies for both publication origins before navigation. See [first-run-terms-block.json](first-run-terms-block.json), [clone-preflight.json](clone-preflight.json), and the rerun's [preflight.json](touch-point-rerun-20260927/preflight.json).

The page became ready in Chrome's Canvas2D compatibility renderer. Each run recorded no generation, editor/provider, or external requests, and no page or console errors. The first run's initial touch point overlapped the jump control; that probe was corrected to start at 45% canvas height.

The single targeted rerun is in [touch-point-rerun-20260927](touch-point-rerun-20260927/). Its drag ran from `(379, 386)` to `(267, 386)` CSS pixels. No further input variants were tried. The full rendered-page capture and failure screenshot are included.

No model calls were made. The browser was not asked to accept legal terms, and no existing profile, account, or original AVD state was changed. The clone emulator was shut down after the rerun.
