# Catalog-backed scene generation

Orbsie supports `geometry: { kind: "asset", assetId, detail, tint? }` alongside procedural geometry. Catalog IDs are a finite schema enum. Provider context supplies the reviewed catalog metadata and asks for a useful mix of existing models and new geometry. Explicit new-model requests take precedence over reuse. The initial collection has ten CC0 Kenney Nature Kit GLBs; its exact bundled license and provenance are in `assets/catalog/`.

The API relay, local ChatGPT companion and browser store independently derive and enforce the request's asset policy. Selected original-model requests apply to the selected stable entity; unselected original-model requests conservatively apply to the creation request. Entities generated under that constraint retain `assetPolicy: "new-only"` across later edits. The server does not trust a model-supplied policy downgrade. Natural-language policy detection currently handles the supported English phrases; broader multilingual and ambiguous mixed-scope intent handling remains to be validated.

Catalog meshes load asynchronously through a bounded cache and are merged into vertex-colored geometry with source transforms. The renderer clones shared geometry before applying formation attributes or an explicit material tint. Pending replacements retain the previous usable shape and collider; new pending assets do not participate in gameplay. Platform and bridge support uses transformed catalog bounds. The current loader performs asynchronous I/O, but GLTF decoding and merging are not yet moved to a dedicated worker; responsiveness under heavy geometry remains an open acceptance gate.

ZIP exports include referenced GLBs, exact license bytes and `used-assets.json`, verified against recorded hashes. Runtime source includes its catalog dependencies. The exported build copies models and attribution into its output. Publication manifest v2 verifies these same binary files and provenance in addition to the independent runtime; historical four-file v1 publications remain supported. Real catalog publication still requires a successful live deployment and anonymous playback check.

`node scripts/verify-asset-browser.mjs` uses deterministic model commands and real asset fetch/decode/render/export. It checks mixed content, preserved export records and rejection of forbidden catalog reuse. Its report explicitly records zero model calls. Live provider evidence is separate under `docs/evidence/provider-e2e/`; procedural-only provider results do not prove mixed catalog generation.

Blender-generated artifacts, a packaged local Blender companion, heavy geometry workers and measured speed improvement are separate unfinished parts of the plan. The checked-in catalog and successful fixture workflow alone do not satisfy those requirements.
